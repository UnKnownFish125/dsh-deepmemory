# 记忆召回评测 · 首次人工复核（Agent-as-judge）

- 时间：2026-10-24
- 数据：生产记忆库（只读，34k docs）
- 用例：45 条记忆改写 query + 15 条真实任务 prompt + 10 条无答案题 = 70
- 方式：每条 case 跑 `/v1/memories/search`（k=8），由 **agent 本人**逐条复核“这条召回我会不会用”
- 判定：`useful_ids`（会用）、`seed_hit`（种子记忆是否召回）、`count_judgment`（ok / too_many / over_recall）

## 结果

| 维度 | 指标 | 值 |
|---|---|---|
| 召回准确（记忆型） | seed_hit | **21/45 = 0.467** |
| 召回准确（记忆型） | precision（有用/召回） | **0.535** |
| 召回准确（任务型） | 任务至少召回 1 条有用 | **12/15 = 0.800** |
| 召回准确（任务型） | precision | **0.324** |
| 召回数量 | count_ok（记忆型） | **36/45 = 0.800** |
| 召回数量 | count_ok（任务型） | **9/15 = 0.600**（多数偏多） |
| 不滥召回 | no_answer 通过 | **5/10 = 0.500** |
| 总体 | precision | 0.475 |
| 总体 | count_ok | 50/70 = 0.714 |

## 关键发现

1. **任务型查询“有料但很吵”**：15 个任务 12 个能召回至少一条有用记忆，但每次 8 条里平均只有 1.5 条会用（precision 0.32），
   且 6/15 属于“召回条数明显偏多”。注入时这些噪声会直接吃掉上下文预算。
2. **记忆型查询近半找不到种子**（0.467），零结果 6/45；典型：
   - `沙箱`（m-006/m-039）→ 库里有沙箱规则却 0 结果；
   - `slots`(m-019)、`文件名`(m-035)、`生命周期`(m-042)、`库存`(m-045) → 0 结果；
   - `安装包`/`电脑`/`WebUI 偏好` → 召回了大量通用偏好（中文、简洁、先方案），真正的那条排在后面。
3. **无答案题一半会硬召回**：火星/南极这类问题返回 0，但“蓝鲸项目密码轮换”“海底光缆检修船”都召回了无关条目
   （例如把“凭据不回显”规则当成答案）。说明缺少“无匹配就该空”的阈值。
4. **最需要的任务反而没召回**：
   - `t-005 怎么把约束写进 literature bias 库` → **0 结果**（这条经验是今天才沉淀的，库里有但没被召回）；
   - `t-013 抽取失败怎么从 pending 恢复` → 只召回一条不相关；
   - `t-015 评测集怎么跑` → 全噪声（评测脚本是今天新加的，尚未沉淀成记忆）。
5. **对“数量合理”的判断**：记忆型 80% 可接受，任务型只有 60%——任务型更适合少而准（3–5 条），当前 k=8 明显偏多。

## 结论（面向 agent 自己）

- 现有召回**对“事实型问答”勉强可用**（约一半能命中种子），**对“任务执行”噪声过高**；
- 注入预算应优先给任务型高相关条目，当前实现按条数灌入会浪费上下文；
- 下一步优先级：① 相似度阈值/空结果判定（治 over_recall）② 任务型重排（治 precision）
  ③ 对“今天新沉淀的经验”做即时索引（t-005/t-015 类 miss）。
